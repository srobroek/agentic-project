# Authoring a layer

A layer is a directory under `templates/` containing a `copier.yml` plus files. It is
generated by `tools/port_assets.py` from the asset source of truth, so author there.

## Steps

1. Add the asset directory to `LAYERS` in `tools/port_assets.py`.
2. Add every new `@@TOKEN@@` to `TOKEN_POLICY`, choosing exactly one of:
   - `required: True` -- no default, so Copier refuses to render without an answer
   - `default: ...` -- a value that is correct for most projects
   - `choices: [...]` -- a closed set, enforced on `--data` input
   - `validator: "regex"` -- enforced on `--data` input
   A token with no policy entry is a hard error. That is deliberate: a policy-less token
   would render blank and ship a broken config.
3. Map each `# OPTIONAL BEGIN <label>` to a condition in `OPTIONAL_MAP`. An unmapped label
   is a hard error.
4. List tokens referenced only by a `_task` command or a `when:` clause in `EXTRA_TOKENS` --
   they appear in no file body, so the scanner cannot find them.
5. Re-port, then `project-setup catalog` to confirm the questions, and
   `project-setup validate --preset <each>` to confirm no preset regressed.

## File naming

| Suffix | Behaviour |
| --- | --- |
| `.template` (in assets) → `.jinja` | rendered; `@@TOKEN@@` substituted |
| anything else | copied byte-for-byte |

MUST NOT give a `.template` suffix to a file containing literal `{{ }}` -- a GitHub Actions
workflow or a justfile recipe body. Only `.jinja` files are rendered, and that is exactly
what keeps `${{ github.sha }}` and `{{ filter }}` intact.

If a file needs *both* substitution and literal `${{ }}`, it still works: the variable
delimiter is `@@`, so `${{ }}` is not a template expression. This is why the delimiter was
changed rather than the files.

## Shared destinations

Never have two layers write the same file. Instead, each layer drops a uniquely named
fragment into a `.d/` directory, and a generator folds them:

| Fragment directory | Generator | Destination |
| --- | --- | --- |
| `.gitignore.d/` | `fold_gitignore.py` | `.gitignore` |
| `.pre-commit.d/` | `merge_hooks.py` | `.pre-commit-config.yaml` |
| `.just.d/` | `gen_justfile.py` | `justfile` import block |
| `.github/quality.d/`, `security.d/` | `gen_caller.py` | the CI caller |

Generators run once, after every layer is placed. A per-layer Copier task would fire before
later layers had contributed anything.

## Tasks

Put the script in `tools/tasks/` and list it in `TASK_SCRIPTS`. A task must be idempotent
and must degrade to a warning when its tool is missing. Tasks run in the destination
directory and require `--trust`, which the CLI supplies because the layers are bundled here.

## Known constraint

An answer that feeds an already-merged file cannot be changed by re-applying:
`merge_hooks.py` refuses a conflicting hook definition rather than overwriting it. Delete the
generated file and re-run to change such an answer. This is covered by
`tests/test_scaffold.py::test_changing_a_merged_answer_is_refused_not_silently_applied`.
